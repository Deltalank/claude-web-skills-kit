# Contributing

Thank you for improving this project.

## Contribution rules

Before contributing, follow these rules:

1. Keep skills focused.
2. Do not turn a skill into a mega-skill.
3. Do not add secrets or private data.
4. Do not invent testimonials, clients, reviews, prices, legal claims, SEO guarantees or security guarantees.
5. Add tests for new skill behavior.
6. Update documentation when behavior changes.
7. Keep examples fictional unless real use has explicit permission.

## Skill checklist

Every skill should include:

- `SKILL.md`
- `README.md`
- `references/`
- `examples/`
- `tests/`

Every `SKILL.md` should include:

- purpose
- when to use
- when not to use
- workflow
- safety boundaries
- output contract
- token policy
- quality gates

## Pull request checklist

- [ ] Scope is clear.
- [ ] No secrets or private data added.
- [ ] Examples are fictional or approved.
- [ ] Skill behavior is documented.
- [ ] Tests or validation prompts were added or updated.
- [ ] Changelog was updated when needed.
